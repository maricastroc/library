# Decisions and open items

## Conventions

- **Everything in English.** Files, routes, components, functions, internal values (statuses, taxonomy ids, sort keys), CSS classes and theme tokens are in English, and so are the interface texts, the prompts sent to the model, the catalog data (synopses, genres, notes) and the evaluation queries. The display label of each internal id lives in `src/lib/semantic/taxonomy.ts`.
- **Books carry the title of their English-language edition.** When a book was never published in English, its title is translated (A Rosa do Povo is The Rose of the People, Fogo Morto is Dead Fire); only titles that are proper names stay as they are, as English editions also keep them (Dom Casmurro, Iracema, Macunaíma, Sagarana, São Bernardo, Mayombe). The shop sells Brazilian editions, so ISBN and publisher still belong to the Portuguese-language edition; `data/seed/catalog.json` keeps that title in `editionTitle`, which is also what the catalog fetch searches for.
- **Stored values were translated too.** On opening, `src/lib/db/migrations.ts` converts an earlier database to the current vocabulary: version 2 translates statuses and taxonomy ids, version 3 translates genres and synopsis sources and rebuilds the text index.

## Architecture

- **Next.js 16 (App Router) + SQLite (`better-sqlite3`)**. The catalog is read in Server Components; writes go through Server Actions and `/api/admin/*` routes. No paid services.
- **SQLite in `TRUNCATE` journal mode, not WAL.** In WAL, command-line scripts closing their connection deleted the `-wal` file while the development server still held it open; the server's writes ended up in an orphaned file. With a plain journal, every transaction ends in the main file.
- **Vectors in BLOBs and brute-force search in memory.** With 220 books (≈2,400 vectors of 768 dimensions, between books and synopsis sentences) the comparison takes milliseconds; a vector index would only add a dependency. The in-memory index is invalidated by a revision counter stored in the database.
- **Server modules are never imported by client components.** Shared constants live in pure modules (`import-types.ts`, `palettes.ts`, `taxonomy.ts`).

## AI

- **Embeddings: `embeddinggemma` (768d). Classification: `gemma4:e4b`.** Both local, through Ollama.
- **The language model works outside the query path.** It reads each synopsis once and stores atmosphere, pace, density, style, experience, themes and a reading portrait. Search uses only embeddings and rules, and answers in tens of milliseconds.
- **Classifier output without `format`/schema.** Measured on this machine: schema-constrained JSON generates ~7 tokens/s and does not scale in parallel; free text with four simultaneous requests reaches ~25 tokens/s. Validation is done in code.
- **Verified evidence.** The classifier must quote passages from the synopsis; each passage is located literally in the text (ignoring accents and case) and discarded if it does not exist. The confidence shown depends on the length of the synopsis and on how many passages survived.
- **A synopsis shorter than 140 characters is not classified.** The book stays in kraft paper and can only be found by keywords.
- **Search**: the query is split into a request and a restriction ("but without being…", "that isn't…", "nothing too…"); the request becomes a vector and is compared with each book's synopsis vector and reading vector; the final order adds requested attributes, penalizes avoided attributes and takes length, pace, genre and matching words into account. "For those who liked X" uses the centroid of the books by X that are in the catalog and excludes those books themselves.
- **When not to answer.** Below a similarity floor the shelf shows nothing; in an intermediate band it shows at most three books and warns that the match is weak. A reference to an author or book missing from the catalog is stated as such, without inventing a resemblance. The thresholds were calibrated with `data/eval/queries.json`.
- **What the catalog cannot know.** A request that only asks for a judgment about reception ("an underrated book", "a bestseller", "the best book you have") is declined with an explanation: the catalog records what a book is about and how it reads, not how it was received. When the judgment comes with something searchable ("an underrated book about grief"), it is set aside, named in the answer, and the rest is searched. A request with no content at all ("a book") asks the reader for more. Before this rule the generic word "book" was enough to match every synopsis, and opposite requests returned nearly the same list.
- **Looking up a title or an author.** The same field takes a name: "woolf", "machado", "magic mountain" bring that author's books, or that book, first, followed by up to three that read like them. A single word only looks up authors; as a title it would hijack requests like "a romance". A name typed with capitals that is not on the shelf ("Stephen King", "Harry Potter") is answered as such, without a resemblance invented from the synopses.
- **If Ollama goes down**, the search route returns keyword results and says so in the interface.

## Data

- **Google Books was left out**: the anonymous daily quota was exhausted (HTTP 429) and there is no key configured.
- **Open Library** provides ISBN, publisher, pages, year and cover. Only Portuguese-language editions from regular publishers are accepted; print-on-demand reprints are discarded and the field stays empty. The year is the earliest among the records of the same work, which for translated books is often the year of an edition; `data/seed/titles.ts` carries the first-publication year for the titles where Open Library was wrong (The Scarlet Letter came back as 1800, Lolita as 1777).
- **Wikipedia (CC BY-SA 4.0)** provides the synopsis: the introduction plus the plot section, with attribution and a link on each book. Most titles come from Portuguese Wikipedia; English-language books added later come from English Wikipedia, chosen per title in `data/seed/titles.ts`. The article is only accepted if it is about the work: the page title or the first sentence must carry the book's title, and author pages are refused. A first version without this rule stored biographies as synopses for about 40 books; they were fetched again and reclassified. On English Wikipedia the article's short description must also credit the author when it names one, which keeps adaptations out: the first fetch of To Kill a Mockingbird found the article on the 2018 play.
- **Synopses from Portuguese Wikipedia were translated into English** after the fetch; the ones from English Wikipedia are kept as written. In translations, mentions of books that are in the catalog use their English titles, other works are named as in the source. The translation is a derivative of the Wikipedia text and stays under the same licence; the link on each book points to the original article.
- **Covers are neither downloaded nor redistributed**; the book page points to the Open Library image. The image is the cover of an English-language edition of the same work, so it matches the title shown; a book with no English edition on Open Library shows its shelf binding instead of a photograph.
- **Price and stock in the initial catalog are demo values** and are marked as such. Once edited at the counter or imported by CSV, they count as real.
- **Bookseller's notes**: the 21 notes in the initial catalog were written for the demo and appear as "sample note". Real notes come from the counter or from the CSV. The AI never fills in this field.
- **CSV import** recognises the headers of `public/catalog-template.csv` and common English variants ("name", "description", "qty"). Headers in other languages are not mapped; a file without recognisable title and author columns is refused with a message listing the headers found.

## Interface

- **A collection on display, not a shelf.** The first version lined the spines up on horizontal shelves and opened each book as two pages, too close to the project that inspired it. The books are now composed into niches, small still lifes of up to about a dozen volumes, each piece on its own support: a cover facing out on a tall pedestal, short runs of standing books, piles lying flat on the floor. There is no continuous shelf line.
- **Composition by rule** (`src/lib/shelf/composition.ts`, pure and tested). Within a niche, the book with a bookseller's note faces out (otherwise the first one), poetry, theater and books of up to 170 pages lie flat with the largest at the bottom, a noted book can stand face-out on a pile, the rest stand in runs of four to seven, and the last book of a run leans on its neighbour at an angle that grows with the group's average pace. One of three orders is chosen per niche by a hash of the group, so groups of the same size don't look alike.
- **A compact collection.** A group flows along the line: each niche is sized to the room left on it (four to thirteen books, never leaving one or two behind), so lines are full instead of holding a single niche with half the width empty. Each niche then settles just under whatever stands above it, so a low niche leaves room for the one below and the collection interlocks; the reading and keyboard order stay line by line. Two slim books can lie across the top of a standing run, as they do in real bookshops. Niches of the same group stand closer together than niches of different groups, label space is only kept where there is a label, a label steps under a bookseller's note instead of colliding with it, and a long group is named again at most every 520 px (640 px on a phone). Compared with the earlier, airier layout (still available with `?density=airy`), the collection is about 36% shorter on a desktop and 19% on a phone, with the books at the same size.
- **Books are 3D objects.** Each book is a box with its spine in front and its cover on the side. Focus or hover lifts it and turns it a third of the way to show the cover, and the books after it in the same run step aside to make room; a lying book slides out of its pile. The cover is only drawn when a book faces out or has been turned once, so the page never renders all 277 covers.
- **Stable DOM, moving coordinates.** Every book keeps its element; reordering or searching only changes its pose (position, rotation, scale, turn), so books travel and turn rather than reappear, and focus is never lost. Off-screen books swap without animating.
- **An answer is a staircase.** The answers leave their niches and stand at the top on pedestals that step down by rank: the closest is the largest and highest, the next two face out lower, the rest stand together. Ranks are roman numerals on the pedestals, and each caption shows only what the engine returned (the atmospheres it matched, a reason). The passage of the synopsis closest to the request is set in the free space, labelled with the numeral of the answer it belongs to; when no answer has one, there is no quote. Arranged by anything other than relevance, or when the match is weak, the answers stand level. "Seen as a list" gives the plain reading.
- **The dust jacket.** Opening a book lifts its cover out of the composition, flies it to the middle of the screen and unfolds the jacket from it: front flap (title, why it was suggested, synopsis), spine, back cover tinted with the book's colour (the AI's reading, the bookseller's note, a barcode drawn from the real ISBN when there is one) and back flap (the edition, price, reservation). Closing folds it and flies it back. On a phone the jacket is unfolded downwards, one panel after another. It is a native modal `<dialog>`, and with `prefers-reduced-motion` it simply appears.
- **The collection is a single Tab stop** (roving tabindex); arrow keys follow the composition, up and down move between rows. The list view gives the same books in a semantic list.
- **The list is an index with a reading plate.** One column per group, because a long list is read downwards: the old three newspaper columns sent the eye back up to the top of the page and put a group of 68 next to one of 4. Each entry is a line of an editorial index: a key of up to three dots (the book's atmospheres, in order, like the coloured labels libraries stick on spines; a hollow kraft dot when it is not yet read), the title, the author, a bookmark when the bookseller left a note, a dotted leader and a locator that follows the arrangement (the year, the price when arranged by price, the roman numeral of an answer, as on the staircase). Group names stand in the margin and stay in sight while their group scrolls; a contents line at the top jumps to each group.
- **The second layer is in the margin, not in the row.** Pointing at or focusing an entry underlines it in pencil, stretches its dots into bands and takes the book out of the list: on the right, the cover turns from spine to face on a small plinth, over a catalogue card with its real classification (atmospheres, pace and density, voice, what it is good for, form, copies, the bookseller's note in handwriting). Nothing in the list moves. Before the first entry is touched, the plate shows the key to the dots. Opening a book flies the jacket out of that cover and folds it back into it, and focus returns to the entry. The plate only exists from 1024 px; on a phone an entry is two lines (title; author, leader, locator) and opens the jacket directly. The plate only follows the mouse when it moves, so scrolling under a resting pointer does not take it away from the keyboard.
- **The list is still one Tab stop.** Arrow keys, Page Up/Down and Home/End move through the entries, and typing the first letters of a title (of a surname, when arranged by author) jumps to it, as in a library catalogue (`src/lib/shelf/listing.ts`, tested). The plate is decorative for assistive technology: each entry's name already carries its atmospheres and the note mark. The list is about a quarter longer on a desktop than the three columns were (one line per book, 277 books), which the contents line, the side heads and typing to jump are there to offset.
- **Spine rules** (`src/lib/shelf/identity.ts`): color = predominant atmosphere, slightly mixed with the second; thickness = pages; height = density and form; number of rules = pace; typeface = genre. The text color keeps a contrast of at least 4.5:1, checked in a test for every combination, including labels and plates.
- **Binding families.** Each book is bound by rule: leather with raised bands until 1879, cloth from 1880 to 1934, three-band paperback from 1935 to 1969, trade paperback from 1970 to 1999, plain cover since 2000; poetry, theater and novellas in paper wrappers, science fiction, fantasy and crime as numbered pocket books, essays, reportage, memoirs and comics in dust jackets. Unread books stay in kraft paper. Ornaments and imprint marks come from the author's name, so one author's books look like a uniform edition.
- **A running head, as in a book.** The opening keeps the large search. When its field passes under the top of the window, a 52 px running head fades in over it: the shop's name in italic, the same search in a single line, and on the right the section the reader is in ("the collection, by atmosphere", "house showcases", "how to read the collection"), replaced during a search by the number of books highlighted and a way to clear it. It is opaque, in the page's own paper, and separated by one hairline the width of the text column, without shadows. The field's pencil stroke only appears on hover, with text, or drawn in vermilion on focus, so at rest the only line is the hairline. Both fields edit one draft, kept in `ShelfExperience`, so what is typed in one is in the other; the search itself, the URL and the results were already shared.
- **The two fields hand focus over.** If the cursor is in the running head when the page goes back to the top, it moves to the large field at the same position, and the other way round when the large field scrolls away; the running head is `inert` while hidden, and the large search is `inert` while it is out of sight under the running head, so Tab never sends the page back up. A search from the running head opens the answer at once instead of animating the opening's height, then scrolls to the answers. With `prefers-reduced-motion` it appears and disappears without moving.
- **How to read the collection, in four parts.** The guide at the foot of the home page tells four ideas in order, each led by a roman numeral rather than a rule and a label: I the binding (the eight specimens on one shelf, grouped by era and by kind, beside the title on wide screens like a title page facing a plate), II the colour (the twelve atmospheres, with three copies of one spine showing what the first, second and third atmosphere each change), III the rules (one spine annotated with what its typeface, rules, height and thickness mean, then how books stand together and the small signs: bookmark, kraft paper, shared ornaments) and IV the AI (four short sentences on what it does and does not do, beside the passages the AI quoted from a real synopsis, picked from the catalogue rather than written for the page). Model names stay, in small print, and the sources and licences close the section as a footer. The rules that draw the books are untouched; only their presentation changed.
- **A table at the door.** The opening keeps its sentence, field and borrowed requests, and adds five real books to the right of "I’m looking for", standing on the title’s baseline: two lying in a pile with a cover propped on top, one upright and one leaning on it, like the table at the front of a bookshop. They are drawn by the same 3D book and binding rules as the shelf, chosen by rule (one per atmosphere, from dreamlike to intense, preferring a bookseller’s note, different bindings and short titles for the books that lie flat), with two titles asked for by name, Harry Potter and the Philosopher’s Stone facing out and The Song of Achilles leaning, which fall back to the rule if they leave the catalogue. Every one of them carries its cover, so turning a book on hover shows it, as on the shelf, and their right edge lines up with the search button. A handwritten “or pick up a book —” answers “or borrow a request —” in the margin, and each book opens its jacket from where it stands. In the markup they come after the field, so the search stays the first stop for the keyboard, and they are one Tab stop with arrow keys, like the collection. The title and the field were set about a sixth smaller so the books have room of their own instead of taking what the title leaves; the books keep their own scale, follow the title only on narrower screens and never push it onto two lines; on a phone they stand above the sentence. While a search is under way they step aside, as the borrowed requests do, so they are not mistaken for answers. Two other directions were tried and set aside: an upper shelf cropped by the top of the page with ribbons hanging from it (no ground to stand on, and it competed with the navigation), and a smaller group of three (less colour, and the note floated away from the books).
- **The running head is opaque from its first frame.** It used to fade in as a whole, so for a quarter of a second the shelf showed through it while scrolling. Now its paper appears at once and only the name, the search and the section title fade and slide in. Each part of the guide also names itself in the running head ("how to read · the colour").
- **The scrollbar is drawn by the page** (`src/components/ScrollRail.tsx`). Styling the browser's own scrollbar with `::-webkit-scrollbar` worked in some Chromium builds but not in Chrome on a Mac set to show scroll bars only while scrolling: there the bar stayed an overlay, invisible until the page moved, and could not be grabbed. With a mouse or trackpad the native bar is hidden and a rail in the shelf's style takes its place on the page and on each flap of the jacket: always visible, the thumb can be dragged, a click on the track jumps there, and it turns vermilion while held. Wheel, trackpad and keyboard scrolling are untouched; on touch screens the native bar stays.
- **State in the URL**: `?q=`, `?sort=` and `?book=`; the browser's back button folds the jacket.

## Counter

- A single password in `ADMIN_PASSWORD`; session in an `httpOnly` cookie signed with HMAC, 12 hours. `src/proxy.ts` guards `/admin/*` and `/api/admin/*`, and every Server Action and route checks the session again.
- CSV import in two steps: analysis with a preview, then writing in one transaction.
- **A desk, not a dashboard.** The Counter has its own stylesheet (`src/app/admin/counter.css`, loaded only by `src/app/admin/layout.tsx`) built from the shelf's materials: paper, ink, hairlines, mono folios and a vermilion margin rule down the page, like a ruled ledger. A rail on the left numbers the seven rooms (01 to 07) and marks the current one with a ribbon bookmark; on a phone it becomes a line of tabs that scrolls the current one into view. Every page opens with the same head (folio, title with one word in italic, a short lede), and each page is then composed for its own job. Rules that would also match public classes (`.field`) are scoped to the Counter, since a stylesheet can stay in the document after navigating back to the shelf.
- **A book record in three tabs.** Editing a book is split by the kind of work: 01 Book details (the bibliographic record, the synopsis with its source, the bookseller's note and the read-only metadata from the sources), 02 AI reading (the reading and where it came from) and 03 Presentation (cover, spine, what each visual trait is derived from, and price and stock beside a proof of how they appear in the jacket). Price and stock live with the presentation because they decide what the reader sees and can do (reserve or be told), but they are saved with the record, as before. The tabs stay mounted, so switching never loses what was typed; the tab is kept in `?tab=`, a dot marks a tab with unsaved changes, and leaving the page with changes asks first. Above 64rem the tab bar sticks to the top and names the book once the head has scrolled away.
- **Two saves, on purpose.** The record and the reading keep separate actions because they mean different things: saving the reading marks it as the bookseller's review, which the AI then never overwrites; saving the record can send the book back to the AI when its title, author, genre or synopsis change and the reading is still the AI's. The record's save bar says which fields are unsaved and, before saving, whether the save will trigger a new reading; an error in a field that sits in another tab names the tab and jumps to the field. Asking the AI for a new reading is a separate block with a confirmation that lists what is replaced, discarded and kept, and what happens meanwhile; while the AI works, the page refreshes itself until the new reading is in.
- **The reading shows its result first.** Atmospheres are shown in order of predominance, then pace, density and voice in one band, good for and themes in another, and the portrait as the closing sentence; each group opens its alternatives only when asked ("change"), and atmospheres can be added, removed and reordered there. The passages the AI relied on are behind "Why this reading?", grouped by the attribute they support and marked when that attribute is no longer in the reading. A narrow spine preview follows the edits on wider screens.
- **Only real numbers.** The day book opens with a sentence built from the catalogue, a band of one slice per book (coloured by its reading, kraft when unread, hatched when the synopsis is too thin, vermilion when the reading failed), and a list of what needs the bookseller, each with a count and a link to the filtered view. A line only appears when its count is above zero; when nothing is pending, the page says so. Nothing is invented to fill an empty state.
- **The catalogue stays a table.** Books are a ledger with a spine chip, the reading as dots and words, and a peek row (synopsis, reading, note) that opens in place, with facets written as words (reading, notes, shelf) whose counts follow the other filters. Old `?filter=` links still work. On a phone the reading folds into the book cell and each facet becomes one scrolling line.
- **Import shows control without being a wizard.** Four steps are named at the top and follow the real state of the file (choose, read and check, review, import). The review sorts every row into new, update, set aside or error with the reason, shows how each column was understood, filters by kind, and only then offers "Import N books". The result is a receipt with links to the new books and to the reader's progress.
- **A showcase is previewed as it will appear.** The list shows each selection as a small exhibition in its own colours with its books standing; the editor keeps a live preview of the home-page band beside the form (the first twelve books, as the home page shows them), so colour, title, introduction and order are judged as the reader will see them.
- **Arranging a showcase is one table, not a sequence of steps.** The title is the page's heading, written in place, with the introduction under it. The selection comes first and stays the main element: one compact row per book with its order, a spine chip, title and author, and the caption in the bookseller's hand, or what will show instead (their note, or the sample note) and a quiet "write a caption" that opens the field in place (Enter keeps it, Esc undoes). Books are reordered by dragging the numbered handle (pointer events, so it works with a mouse and a finger alike, and the other rows open a gap where the book will land), by the arrow keys on the handle, or by the ↑ ↓ buttons; every move is announced. Removing a book needs no confirmation because it can be undone from the slip that replaces it. Adding books sits directly under the list: the search by title or author leads, marks the books already chosen, and Enter adds the first one available; "Suggest from the idea" asks the semantic search with the title and introduction, shows five books with a way to see the rest, lifts the reasons most of them share into one line so each book only lists what is its own, and quotes the synopsis passage when the engine found one. The reasons are the engine's own; nothing is written for the occasion. When the idea changes after asking, the panel says so.
- **Saving and showing are said apart.** The model has only `published`, so the page has only two states: on display or a draft. The switch says who can open the showcase and, when it differs from what is saved, that it takes effect on saving; the save button names what is unsaved (title, introduction, books, captions, colour, putting it on display) and leaving with unsaved changes asks first. There is no fixed save bar: beside the form the column with the preview, colour, display, link and save sticks to the top only when the window is tall enough to hold it, and scrolls on its own rather than being cut; on a phone it follows the list, and a short unsaved line with a save button appears under the introduction. Deleting stays apart, at the foot of the page.
- **Reservations are correspondence, with only the states that exist.** A request is `new`, `fulfilled` or `cancelled`, and of kind `reservation` or `notice` (the kind is set by the stock when the reader writes). The page adds no state of its own: what it shows besides is derived. Letters wait oldest first, with their age; a notice whose book is back in stock says so, a reservation whose book has no copy left says that, and the button that files a notice reads "Mark as told" because that is what `fulfilled` means for it. There is no "answered" state because nothing records a reply: the bookseller writes from their own mail or phone (the contact is a `mailto:` or `tel:` link) and files the request afterwards. Filed requests are listed with their outcome and can be reopened.
- **The evaluation page says how far its numbers go.** Before any figure it states that the grades come from a local model, not a reader, that nDCG@5 is relative to the books the three engines found together, and that empty answers score 0; it also says when the catalogue has changed since the run, counting the books added and edited after it. Beside the means, each graded query is counted as better, level or worse (a difference under 0.05 is level): the shelf beats keywords on 18 of 24 queries but is level with embeddings alone (better on 9, worse on 10), and the page says so in a sentence derived from those counts. By kind of question, a gap is flagged only when it is at least 0.05, with a note that one query moves a mean of four or five by up to 0.25.
- **The bookshop's details are edited against proofs.** Each of the five fields is lettered, and the same letters mark where it appears: the masthead, the foot of a cover, the signature under the bookseller's notes and the showcase page. Focusing a field highlights its places in the proofs, which follow what is typed before it is saved.

## Open items

- The evaluation uses a local model as the relevance judge. Human judgment of the same lists is still missing.
- 47 of the 376 titles researched had no usable Wikipedia article (or only had the author's page, which is refused). In the 277-book catalog, 201 have the ISBN of a Portuguese-language edition and 246 have a cover.
- The first 200 books were chosen by the quality of their records, which favored classics. A batch of 20 contemporary books (1987–2021: Harry Potter, A Game of Thrones, The Hunger Games, Klara and the Sun, Norwegian Wood, The Road, among others) was added later; their slugs are listed in `data/seed/additions.json`, which the seed always includes. Portuguese-language authors were then 114 of the 220 books and English-language ones 62, so 57 English-language books followed (Middlemarch, Beloved, Catch-22, Giovanni's Room, Wolf Hall, Interpreter of Maladies, Death of a Salesman, Watchmen, among others), bringing them to 119; the other 44 are in other languages. Their synopses come from English Wikipedia, which also covers Gone Girl, Where the Crawdads Sing and Life of Pi, left out before for lack of a Portuguese article. The batch favours new authors: eleven more English titles by authors already in the shop are researched and held back (Sense and Sensibility, Dubliners, The Grapes of Wrath, Orlando, Never Let Me Go, Half of a Yellow Sun, The Bluest Eye, Blood Meridian, I, Robot, Parable of the Sower, And Then There Were None); `npm run db:seed -- --add=slug,…` brings them in.
- No per-user authentication, no payment, no e-mail sending: a reservation only records the request for the bookshop to answer.
- Rule-based query interpretation covers the most common English negations; unusual constructions pass through as free text. Queries written in Portuguese are no longer interpreted.
- Rate limiting is in memory, per process.
- There are no automated browser tests; the flows were checked by hand.
- Browsers submit a textarea's line breaks as CRLF, so every save of a synopsis with paragraphs used to count as a changed synopsis: the source credit was replaced by "Bookshop catalog" and an AI-read book was sent back to the AI. Submitted text is now normalised before comparing. Books saved from the Counter before this fix may have lost their Wikipedia credit; none had been saved in this database.
- The Counter's evaluation report (`data/eval/results.json`) predates the 57 English-language books and the renamed titles; it needs `npm run ai:eval -- --judge` again before its numbers describe the current shelf.
